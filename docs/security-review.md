# Security review — Gate 7.2

Date: 10 Oct 2026. Scope: the SafeWaste app as built through Gate 6 (Clerk sign-in still postponed; the
development test login is used). Each line says what is in place, how it is proven, and what remains.

## Access control

| Check | Status | Evidence |
|---|---|---|
| Every service and query starts with a database role check | ✅ | `tests/permissions/matrix.test.ts` — 6 roles × 72 functions; denied → 403, allowed → passes the check |
| EFDA officer is refused by every write | ✅ | same test ("efda_officer is refused by every write"); Workflow Engine refuses efda before reading a row |
| Hospital roles only see their own facility, inside SQL | ✅ | hospital query tests; certificate / invoice / label downloads return 404 for another facility (no existence leak) |
| Driver actions checked against the current trip assignment in the transaction | ✅ | `tests/integration/pickup.test.ts` (reassignment: former driver 403) |
| Disposal operator must belong to the DISPOSAL_SITE | ✅ | `tests/integration/disposal.test.ts` (operator without site 403) |
| Role checks read the database, never Clerk metadata | ✅ | `src/server/auth/current-user.ts` |
| Development sign-in bypass refused in production | ✅ | `src/lib/env-schema.ts` (DEV_AUTH_BYPASS), unit tests; e2e test identities (`e2e_…`) only with `DEV_AUTH_BYPASS=1` |

| Check | Status | Evidence |
|---|---|---|
